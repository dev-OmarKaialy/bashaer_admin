# Admin accounts (Firestore `admins` collection)

The admin app signs in with a **username and password** that are checked
against a document in the Firestore `admins` collection. There is no Firebase
Auth.

## Fields of an admin document

The document id can be anything (an auto-id is fine).

| Field | Type | Required | Value |
|---|---|---|---|
| `username` | string | yes | What the admin types to sign in, e.g. `admin`. It must match exactly, case included. |
| `salt` | string | yes | Generated by the tool below (32 hex characters). |
| `passwordHash` | string | yes | Generated by the tool below (64 hex characters). |
| `iterations` | number | yes | Generated by the tool below (currently `20000`). **New field.** |
| `displayName` | string | no | Name shown in the account menu, e.g. `عمر`. **New field, optional.** |
| `updatedAt` | timestamp | no | Not used by the app; keep it if you like. |

Hash scheme: `passwordHash = hex(PBKDF2-HMAC-SHA256(password, salt bytes, iterations, 32 bytes))`.
The salt is used as raw bytes, decoded from its hex string.

## Set (or reset) a password

1. In `D:\projects\bashaer_admin`, run:
   ```
   fvm dart run tool/admin_password.dart
   ```
   Type the new password twice (at least 8 characters; nothing is shown while
   you type).
2. Open Firebase console → Firestore → `admins` → the admin's document, and:
   - **replace** `salt` with the printed salt (string),
   - **replace** `passwordHash` with the printed hash (string),
   - **add** `iterations` as a **number** with the printed value.
3. Sign in to the admin app with `username` and the new password.

**Your existing `admin` document** has a `salt` and `passwordHash` from an unknown
scheme. The app can't check them, so sign-in reports the account as not set up
until you do steps 1–2 for it.

Changing `salt`/`passwordHash` signs that admin out on every device the next
time the app starts.

## Add another admin

Add a document in `admins` with a new `username`, then follow the steps above
for its `salt`, `passwordHash` and `iterations`.

## Security note

Without Firebase Auth, Firestore can't tell an admin's request from anyone
else's. So the rules allow public reads of `admins` (the app must read the hash
to check the password) and public writes to the collections the admin edits.
The rules still check the shape of every write and block writes to `admins`.
The login screen keeps casual users out; it does not protect the data from
someone who extracts the Firebase config from the app. Moving to Firebase Auth
later only needs changes in the auth feature and the rules.
